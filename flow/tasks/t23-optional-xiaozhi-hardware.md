# T23 Optional Xiaozhi hardware mode

- Status: `CODE_AND_BUILD_CONFIRMED / HIL_NOT_RUN`
- Requested: 2026-09-10.
- Scope: Windows 软件总开关、主进程硬件命令门、仅 EasyInput 状态表达；不烧录或操作硬件。

## 用户目标

DeskMate 要能分享给只有 EasyInput 开发板、没有小智云台的同学使用。Windows 软件与 EasyInput 固件提供办公效率主链；小智的实体屏幕、表情与舵机是可选载体，不是 AI 陪伴或核心软件能力的前置条件。

## 设置入口

在设置中提供一个明确的总开关：**启用小智硬件扩展**。

说明文案：关闭后停用小智实体屏幕、表情和动作控制；语音陪伴、语音输入、提示词及 EasyInput 按键仍可正常使用。

- 一次关闭全部小智硬件功能，不要求用户逐项关闭或删除配置。
- 选择保存在本机，重启后仍生效；重新开启时保留既有设置，不自动重放旧动作。
- 新用户可明确选择“仅使用 EasyInput”；升级不擅自改变已有用户的启用选择。
- 状态明确区分“已关闭”“已启用但未连接”“已连接”。关闭不是故障，不反复弹出未连接提示。

## 关闭范围与保留能力

关闭范围：

- 小智实体屏幕的眼睛、表情和工作/对话状态下发。
- 舵机手动控制、点头、摇头、环视、跳舞、自定义舞蹈和自动情境动作。
- 与这些实体动作绑定的触发、排队和专属配乐，不在无小智模式下假装已执行。
- 不必要的小智连接重试、动作等待和缺席告警；不影响 EasyInput 自身的连接与诊断。

保留能力：

- AI 语音陪伴、后台语音唤醒、人设、短期上下文和已有长期记忆能力。
- 电脑麦克风与扬声器的语音链路；已有的 EasyInput 音频来源选择按自身能力与用户配置处理，不依赖小智。
- 听写/语音输入、文字整理、历史、词库、提示词工作台和场景切换。
- EasyInput 按键、旋钮、快捷键配置与同步。
- Codex 任务查询、语音提醒和白名单应用启动。
- 软件中的陪伴形象/会话状态可以保留，不冒充实体小智已连接。

## 实现边界

- 不是只隐藏按钮：主进程的能力判断、语音工具、自动动作、状态发布与硬件命令出口都必须遵守同一个开关。
- 关闭后，请求实体动作应明确说明“小智硬件扩展已关闭”，不能编造执行成功，也不能阻塞普通对话。
- 如果关闭时存在动作，按现有已冻结停止/急停合同安全结束并取消待执行动作；完成前不得隐藏必要的停止入口。断线时不能宣称实体已停止或已断电。
- 重新启用仍遵守真实连接、限位、回中和急停等既有安全边界；不自动驱动舵机。
- 软件总开关不代表切断硬件电源，不新增协议，不改 Flash/NVS 布局；不自动烧录、不代用户授权任何设备写入。
- 同一产品维护两种组合：Windows + EasyInput，以及 Windows + EasyInput + 小智；不复制另一套语音流程或另开一份软件工程。

## 后续验收

1. 只接 EasyInput、不接小智，关闭扩展后启动和重启均无持续告警；EasyInput 连接正常。
2. 听写、提示词呼出/选词/复制、场景键、AI 陪伴、唤醒和 Codex 提醒按既有合同工作，不等待小智。
3. 软件按钮、实体快捷键、语音及自动情境入口都不能绕过关闭状态向小智下发动作或表情；已有配置与记忆不被删除。
4. 动作进行中关闭能安全收尾，重开不重放旧队列；无真实回执不宣称硬件停止成功。
5. 接回小智并显式开启后，原有能力可恢复，且不影响仅 EasyInput 模式。
6. 分享包不得携带开发者的 API Key、个人提示词、语音记录、记忆或设备凭据；接收者自行配置账号，并按独立授权流程使用匹配固件。

当前实现已加入本机持久化总开关、关闭时的安全清理、主进程实体命令门、自动动作暂停以及“仅 EasyInput”状态。升级用户默认保持启用；重新启用不重放动作。桌面完整测试、Windows 打包、原生桥 Host 测试和 EasyInput ESP-IDF 固定分区构建均已通过；仍需分别做“仅 EasyInput”和重新接回小智的用户真机验收。当前 T22 按键同步与语音回归不因此自动关闭。
