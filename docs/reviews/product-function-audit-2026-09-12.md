## 2. 优先问题

### A01 / P1：导入配置、恢复默认会替换语音历史

位置：`src/pages.jsx:1962` 附近的 importConfig、`src/pages.jsx:1967` 恢复默认，`src/store/appStore.js:113` serializeConfig、`:178` reduceAppState。

- 导出配置主动写入 `history: []`，合理地避免导出正文；但导入时执行整份 replace，把现有历史覆盖为空。
- 恢复默认直接将整个 state 替换为 defaultState，而非仅重置设置。defaultState.history 来自 appData 的四条演示记录。
- 本轮合成数据：原历史 1 条 → 导入刚导出的配置后 0 条；恢复默认后 4 条演示记录，原测试记录不再存在于列表。
- 这不是“已从所有存储彻底删除”：IndexedDB 录音和 SQLite 记忆可能仍保留，反而容易产生孤立数据。

建议：配置导入只合并明确允许的配置字段，保留历史/runtime；重置设置与清空数据分开，显示影响范围并确认。初始历史改为空，演示数据仅测试模式使用。未修前不要在真实数据上测试这两个操作。

### A02 / P1：20 天保留与删除范围没有覆盖所有原始副本

位置：`electron/companion-memory.cjs:633`、`electron/memory-journal-service.cjs:170`、`src/pages.jsx:880`、`:923`、`:1206`、`src/store/recordingStore.js:43`、`src/store/appStore.js:241`。

- 日终的 20 天策略清理 SQLite conversation_turns 和对应 outbox，并受总结/远端回执门保护；这是已经实现的能力。
- 听写同时在 renderer 历史/localStorage 中保留文字，并将录音 Blob 写入 IndexedDB。未找到同一保留策略对这两处的清理路径；不能把记忆库清理说成软件全部原始数据清理。
- “彻底忘记全部”会清理本地记忆表、上下文及受管投影，但不是语音历史/IndexedDB 的全产品删除，也不应删除 KnowledgeOS Raw。
- 历史“清空”吞掉录音删除错误后仍清列表并提示清空成功；可能留下无法从列表访问的录音。
- 文字历史不断累加；localStorage 写入失败被忽略，不能以页面中的数据还在来保证已可靠保存。

建议：先明确录音是否默认保留、独立期限和跨存储数据关联；删除/保留策略显示真实覆盖范围和失败项。必须用临时数据验证，不能为审计直接清用户数据。

### A04 / P2：陪伴提醒仍是演示，不是个人提醒调度器

`src/pages.jsx:526` 显示固定“14:30 准备产品周会材料”，并明确写了演示，点击只提示待接入。

日终记忆定时器和 Codex 状态播报已经实现，不能与“提醒我某时做某事”的个人提醒混为一谈。建议先移走固定日程卡；若确定要做提醒，再实现创建、确认、取消、到时、错过补偿的完整闭环。

### A05 / P2：记忆策略编辑可能被 30 秒自动刷新覆盖

位置：`src/pages.jsx:602` refreshMemory、`:619` 定时刷新、`:785` 起的策略编辑区。

刷新无条件 setMemoryPolicy(policy)，而时间、来源、小时整理、保留天数都在同一个 state 中作为未保存草稿编辑。停留超过刷新周期，或搜索/切换过滤触发刷新，可能丢失未保存输入。代码路径确认；真实界面录屏复现尚未执行。

建议：分离已保存状态与 draft，dirty 时不覆盖草稿；保存失败保留草稿。另补 searchIndex、chooseKnowledgeOsAdapter、syncKnowledgeOs 等 UI 入口的统一异常提示，避免 Promise 拒绝变成“没反应”。

### A06 / P2：词库替换规则输入框的 React key 随输入变化

`src/pages.jsx:1256` 使用 `${rule.from}-${index}` 作为整行 key。修改左侧原词会改变 key，导致整行重新挂载，存在逐字输入失焦/光标重置问题。建议规则使用稳定 ID；需补连续输入和中文输入法验收。

### A07 / P2：自定义场景只有新增，缺少完整管理入口

`src/PromptKeySettings.jsx:97`、`src/PromptWorkbenchPage.jsx:101` 只提供创建场景弹窗；后端 `prompt-workbench.cjs:171` 能 save-scene，但现有 UI 没有既有场景改名入口，也未找到场景删除命令。用户误建场景后无法从正常页面撤销这个结果。

建议：加轻量“管理场景”：改名、排序、删除空场景；有提示词时先迁移，保护最后一个场景。属于补管理闭环，不是修改 Tab 或重做按键编辑器。
