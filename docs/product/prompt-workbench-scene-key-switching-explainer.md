# DeskMate 提示词工作台与多场景按键切换说明

> 文档用途：课程作业说明、产品功能介绍和跨窗口开发交接。  
> 当前版本：2026-09-11，DeskMate T22F 软件实现。  
> 说明范围：提示词工作台、场景切换、EasyInput 八键与旋钮的联动原理。

## 1. 功能要解决的问题

EasyInput 开发板只有 8 个按键和 1 个旋钮。如果每个实体按键永远只能绑定一个固定功能，那么语音、回车和 AI 陪伴等基础功能占用几个按键后，留给开发、剪辑、办公等工作的按键很快就不够用了。

DeskMate 的解决方式不是继续增加实体按键，而是增加一层由电脑软件管理的“工作场景”：

- 同一个实体键在不同场景下可以执行不同动作。
- 提示词列表也跟随场景切换，只显示当前工作更可能用到的内容。
- 场景切换发生在 Windows 软件中，不需要每切一次场景就重写开发板配置。
- 用户只需要记住固定的基础键、Tab 和旋钮，不需要记大量快捷键组合。

它把有限的硬件输入扩展成一套可切换的效率工作台。

## 2. 当前交互方案

### 2.1 按键分工

| 输入 | 默认功能 | 是否随场景变化 |
| --- | --- | --- |
| KEY1 | 语音输入 | 否，全局共用 |
| KEY2 | 回车 | 否，全局共用 |
| KEY3 | 呼出 AI 语音陪伴 | 否，全局共用 |
| KEY4 | 弹出提示词页；再次按下时复制并收起 | 否，全局共用 |
| KEY5 | 当前场景快捷动作 1 | 是 |
| KEY6 | 当前场景快捷动作 2 | 是 |
| KEY7 | 当前场景快捷动作 3 | 是 |
| KEY8 | 粘贴 | 否，全局共用 |
| 旋钮 | 提示词页打开时，上下选择提示词 | 不改变其他软件中的原有作用 |
| Tab / Shift+Tab | 下一个场景 / 上一个场景 | 同时切换提示词和 KEY5～7 |

KEY1、KEY2、KEY3、KEY4、KEY8 和旋钮属于全局配置；KEY5、KEY6、KEY7 属于当前场景。这样既保留稳定的肌肉记忆，又给每个工作场景留下 3 个可自由变化的实体键。

默认配置只是推荐方案。用户仍可在“按键配置”页面重新设置，但任何实体键修改都需要经过预览、确认和写入后才会真正作用于开发板。

### 2.2 选择和使用提示词

一次完整操作如下：

1. 用户正在 Codex、剪映、Word 或其他工作窗口中操作。
2. 按 KEY4，DeskMate 记录当前工作窗口，并把已经存在的主窗口显示到“提示词”页面；它不是另开一个重复窗口。
3. 页面自动恢复上一次使用的场景和该场景中上一次选中的提示词。
4. 转动旋钮，在当前场景的提示词列表中向上或向下选择。
5. 右侧区域显示完整提示词，方便确认内容。
6. 再按一次 KEY4，DeskMate 把选中的完整提示词写入剪贴板，校验写入成功后收起主窗口，并把焦点还给原工作窗口。
7. 按 KEY8，将提示词粘贴到当前输入框。
8. DeskMate 不自动发送回车，用户仍保留最终检查和提交权。

电脑键盘 Enter 也可以确认复制；如果是误打开，按 Escape 可以取消并收起，不修改剪贴板。

## 3. 场景如何联动提示词与多按键

DeskMate 默认提供 Web Coding、视频剪辑和高效办公等场景，也允许继续增加自定义场景。

切换场景时，软件会同时完成三件事：

1. 把 `activeScene` 更新为新场景并保存，下次启动继续停留在这里。
2. 切换提示词列表、当前选中项和该场景自己的排序。
3. 切换 KEY5～7 的动作路由，并可用一句简短语音播报当前场景。

例如：

| 场景 | KEY5 示例 | KEY6 示例 | KEY7 示例 |
| --- | --- | --- | --- |
| Web Coding | 全选 | 保存 | 复制 |
| 视频剪辑 | 播放/暂停 | 分割 | 撤销 |
| 高效办公 | 全选 | 复制 | 保存 |

这些只是初始示例。每个场景的 KEY5～7 都可以独立配置为：

- 常用动作：全选、复制、粘贴、撤销、保存。
- 自定义快捷键：例如 `Ctrl+K`、`Space`。
- 复制一条固定提示词，但不自动发送。
- 打开已经加入白名单的应用。
- 禁用该键。

Tab 和 Shift+Tab 在“提示词”与“按键配置”两个页面中使用同一个场景状态，因此不会出现两个页面分别停留在不同场景的问题。在文字输入框、快捷键录制框和弹窗中，Tab 仍保持正常的输入或焦点切换作用，不会误切场景。

## 4. 提示词工作台能做什么

当前软件内置 80 条用户提供的提示词模板，并提供以下管理能力：

- 按场景展示提示词。
- 按标题、关键词和正文搜索。
- 收藏和最近使用记录。
- 查看个人提示词和回收站。
- 编辑内置提示词时创建个人副本，不覆盖原始模板。
- 新建、编辑、删除和恢复个人提示词。
- 在当前场景的完整列表中使用“上移/下移”调整顺序。
- 导入和导出本地备份。

排序只允许在“当前场景、完整列表、无筛选”的状态下进行。搜索结果、收藏、最近、个人、回收站和跨场景列表都是临时视图，不能反过来破坏场景的正式顺序。

提示词页面采用固定高度的左右布局：左侧用于快速选择，右侧尽量显示完整正文。左右区域独立滚动，旋钮选择只滚动提示词列表，不推动整个 DeskMate 页面。

## 5. 实现原理

### 5.1 总体数据流

```text
EasyInput 实体按键/旋钮
          │
          ▼
Windows InputBridge 识别设备事件
          │
          ▼
Electron 主进程校验动作与当前前台状态
          │
          ▼
PromptWorkbenchController 读取 activeScene
          │
          ├── KEY4：显示页面 / 复制并收起 / 恢复原窗口
          ├── 旋钮：移动当前提示词选择
          ├── Tab：切换场景、列表和 KEY5～7 路由
          └── KEY5～7：执行当前场景的本地动作
```

开发板只负责报告“哪个键被按下”或旋钮方向。当前场景、提示词正文和 KEY5～7 的实际含义由 DeskMate 主进程管理。

### 5.2 为什么场景切换不需要反复写开发板

KEY5～7 写入开发板的是稳定的 DeskMate Host Action 路由标识，而不是某个场景的提示词正文或具体快捷键。开发板按键触发后，Windows 软件再根据当前 `activeScene` 查找真实动作。

因此：

- 切换场景只是切换电脑端状态，不写 NVS。
- 修改一个场景不会破坏其他场景。
- 可以随时新增提示词和修改快捷动作，不必重新编译固件。
- 提示词正文不会进入开发板，避免存储空间、隐私和固件升级问题。

### 5.3 全局键与场景键的状态模型

概念上可理解为：

```json
{
  "activeScene": "coding",
  "globalKeys": {
    "KEY1": "voice-input",
    "KEY2": "enter",
    "KEY3": "companion-call",
    "KEY4": "prompt-open-copy-hide",
    "KEY8": "paste"
  },
  "scenes": {
    "coding": { "KEY5": "select-all", "KEY6": "save", "KEY7": "copy" },
    "video": { "KEY5": "play-pause", "KEY6": "split", "KEY7": "undo" }
  }
}
```

这是原理示意，不是用于导入的软件配置文件。真正配置包含版本、修订号、校验和受限动作标识。

### 5.4 本地持久化与冲突保护

提示词工作台数据由 Electron 主进程保存，而不是由 React 页面直接写文件：

- 使用版本化本地 JSON 存储场景、选中项、排序、个人提示词、收藏和使用记录。
- 写入时先生成新文件，再原子替换，并保留上一个快照。
- 使用递增修订号检测两个页面同时编辑造成的冲突。
- 导入文件先完整校验，校验失败不会覆盖现有数据。
- 内置模板与个人修改分开保存，删除个人副本不会损坏原始模板。

## 6. 前台窗口与按键冲突如何处理

KEY4 调出提示词时，主进程先记录原来的前台窗口。复制完成后，原生输入桥恢复这个窗口，再由用户按 KEY8 粘贴。这样可以避免提示词复制完以后焦点仍停在 DeskMate 中。

页面快捷键有明确的所有权：

- 提示词页面前台且未编辑时，旋钮和 Tab 由工作台使用。
- 搜索框、编辑器、输入法组合输入和弹窗打开时，不抢占 Tab、Escape 等输入。
- AI 语音流程正在处理取消动作时，Escape 仍优先取消语音，不会顺带隐藏窗口。
- KEY4 复制后会读取剪贴板进行校验；写入失败时保留页面，不假装已经复制成功。
- 任何复制动作都不会自动发送 Enter。

## 7. 安全和隐私边界

- React 渲染页面不能直接访问 Node API、设备原始路径或密钥。
- 自定义快捷键必须通过格式和允许键校验，再交给本地输入桥执行。
- “打开应用”只能选择已经登记的白名单应用。页面只保存不透明 ID 和显示名称，不接收任意程序路径、命令或参数。
- 提示词只复制到剪贴板，不作为系统命令执行。
- 诊断中不记录提示词正文、剪贴板内容、目标窗口标题或完整设备路径。
- 修改开发板配置必须先读取，再显示差异预览，由用户明确确认，最后回读验证；软件升级不会偷偷写板。

## 9. 当前完成度

已经完成的软件能力包括：

- 提示词工作台和 80 条模板管理。
- 场景状态持久化及 Tab/Shift+Tab 切换。
- 全局键与 KEY5～7 场景键分层。
- KEY4 弹出、复制、收起和焦点恢复。
- 旋钮前台选词的软件接收逻辑。
- 常用快捷动作、自定义快捷键、固定提示词、白名单应用和禁用动作。
- 场景内提示词上下排序。
- 配置预览、确认和回读流程。

自动化测试和 Windows 构建已经通过。已有用户实测确认 KEY3 可以呼出 AI 陪伴、KEY4 可以弹出并返回；旋钮选词、KEY8 实体粘贴以及不同场景 KEY5～7 的最终组合仍应在连接 EasyInput 后重新做一次完整真机验收。软件实现完成不等于这些实体交互已经全部验收。

## 10. 作业摘要

本功能利用“软件场景路由”解决实体按键数量有限的问题。用户通过 KEY4 快速调出提示词工作台，用旋钮选择提示词，再由 KEY4 复制并返回原工作窗口、KEY8 粘贴。Tab 切换工作场景时，提示词列表和 KEY5～7 的功能同时变化，而语音输入、回车、AI 陪伴、提示词入口和粘贴等基础键保持不变。开发板只发送稳定的按键事件，具体场景和动作由 Windows 软件管理，因此切换场景不需要重复写入固件。该设计兼顾了操作速度、肌肉记忆、可扩展性、配置安全和用户最终确认权。
