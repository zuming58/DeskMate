# T53 natural interruption and reminders

Status: `T53_NATURAL_BARGE_REMINDERS_V1_FROZEN`

Software only. Supersedes T49 ordinary final-only gating and T52's limited reminder phrase interpretation. Reference comparison: T21B allows confirmed/distinct partials; T21D adds 500 ms observation; T49 defers all ordinary partials; T52 retains that gate. T53 restores early yielding with 250 ms current-item evidence and meaningful confirmed text or two consistent distinct partials. No VAD-only cancellation, extra recognizer, or model call before interruption. Explicit commands retain immediate current-item priority. Echo, filler and pure-number candidates remain rejected. Duplicate partials neither create evidence nor erase it. A matching final starts one replacement turn; inconsistent final cannot replace the accepted utterance with unrelated text. Waiting for a final is no longer a prerequisite for yielding playback. The 250 ms evidence floor is not an end-to-end latency promise.

Reminders retain local persistence, scheduler, receipt-based spoken confirmation and T52 delivery semantics. Clear requests use the local parser. Polite requests precede generic capability queries; common reminder synonyms and relative durations are accepted. Unqualified 1–12 hours are ambiguous unless explicit period/context resolves them; never silently roll a past ambiguous time to tomorrow. Near-time language may resolve the next nearby occurrence using the local clock. Clarification retains content and accepts short confirmations/corrections, asking only for missing data. Flexible reminder turns may use one bounded structured extraction call with current local time/timezone, bounded recent context and pending draft; no background or all-chat classification. Model output cannot write files or invent a saved receipt. Generation checks prevent stale asynchronous results from saving after cancellation/replacement. No credentials or reminder contents enter diagnostics.

Acceptance: early ordinary interruption, short speech, echo/noise, duplicate partial, mismatched final, preserved follow-up audio; polite/relative/AM-PM/current-clock reminders, yes/no/date follow-ups, negation, cancellation, async stale/error results, visible store and scheduler delivery. Full tests, desktop package verification and isolated UI; actual voice/audio acceptance remains user-owned.
