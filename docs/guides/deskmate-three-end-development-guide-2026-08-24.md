# DeskMate 三端软硬件开发指导书

版本：2026-08-24 · V2 专用最新版  
适用对象：第一次做双 ESP32 与 Windows 软件集成的开发者  
产品范围：DeskMate Windows 软件 + EasyInput ESP32-S3 总控固件 + 小智 ESP32-S3 云台固件

> 核心路线：先冻结硬件与恢复基线，再开发正式 EasyInput 总控固件；先用模拟器证明协议，再接三根 UART 线；先让屏幕变化，再开放舵机。无硬件笔记本负责代码、宿主测试和构建，有硬件电脑负责独立审计、烧录授权和真机验收。相似功能组成一个小功能包，包内完成后立刻做软硬件联调和旧功能全量回归，通过后锁定，再进入下一包。摄像头、温湿度和其他外挂最后再加。

## 1. 这份指导书给出的最终结论

### 1.1 三端责任

- DeskMate Windows 软件是产品的大脑和总编排器：负责语音工作流、ASR/LLM/TTS、Codex/Workbody 等 Agent 状态、用户设置、历史、诊断和行为策略。
- EasyInput 是外部硬件总控和 V1 唯一音频端点：负责八个实体按键、旋钮、板载麦克风、板载扬声器、USB/BLE/HID，把桌面命令可靠转发给小智，并把小智状态返回桌面。
- 小智云台是安全执行节点：V1 负责 128×64 OLED、大眼睛/表情和双舵机；本板麦克风、功放和扬声器保留但 DeskMate 模式默认不初始化。它只执行白名单高层动作，不直接理解任意自然语言，也不自己猜电脑任务状态。

### 1.2 两块板怎么通讯

DeskMate Link v1 推荐使用三线、全双工、3.3 V TTL UART：

```text
EasyInput J4 TXD0  ─────────→  小智 RX
EasyInput J4 RXD0  ←─────────  小智 TX
EasyInput J4 GND   ──────────  小智 GND
EasyInput J4 3V3   ── 不连接 ──  小智电源
```

两块板各自供电，只共享信号地。UART 只传控制、状态和确认，不传实时音频。首版建议 115200 baud、8N1、无硬件流控；正式实现使用 UART1 驱动映射到物理 TX/RX 引脚，把应用日志迁移到 USB Serial/JTAG。ESP32-S3 ROM 启动文本仍可能短暂出现在物理 TX 上，接收器必须只接受合法帧并丢弃其他字节。

### 1.3 为什么不是 USB、BLE 或 Wi-Fi

- UART：三根线、离线可用、时延确定、调试清楚，最适合第一版控制和状态链路。
- USB 板对板：涉及 Host/Device 角色、供电和现有烧录接口冲突，不适合第一版。
- BLE：小智当前构建未启用，协议、安全和资源成本更高。
- Wi-Fi：适合以后传音频或高速数据，但会引入配网、发现、鉴权、路由器和断网恢复，不应阻塞第一条硬件闭环。

### 1.4 现在先不加什么

第一阶段不加摄像头、温湿度、手势或其他传感器。当前没有已确认摄像头；用户也未安装 PAJ7620U2，且该模块只能识别离散手势，不能提供人脸坐标。主链稳定后，首版人脸检测优先放在电脑端，再向小智发送归一化坐标。

### 1.5 V1 硬件冻结决定

| 项目 | 已确认决定 |
| --- | --- |
| 电脑连接 | Windows 只把 EasyInput 作为日常 USB 主设备 |
| 物理位置 | 小智板与 EasyInput 紧邻，最终叠放在 EasyInput 下层 |
| 语音采集 | 统一使用 EasyInput 板载麦克风 |
| 语音播放 | 统一使用 EasyInput 板载扬声器 |
| 小智音频 | 实物保留，DeskMate 模式默认关闭 |
| 板间链路 | `TX/RX/GND` 三线 UART，只传控制和状态 |
| 原型供电 | 两板独立供电；J4 `3V3` 留空 |
| 云端对话 | 当前原固件仅作对照和恢复；最终产品转为 DeskMate 本地运行 |

这套选择优先保证一根电脑 USB、最少网络依赖和最少同时活动外设。完整可执行基线见 `docs/architecture/deskmate-v1-hardware-baseline.md`。

## 2. 当前三端真实基线

### 2.1 DeskMate Windows 软件

当前已经具备 Electron 安全壳、系统托盘、底部语音胶囊、统一 VoiceWorkflow、千问 ASR、历史记录、目标输入框输出、EasyInput Raw Input 桥、快捷键捕获、按键/旋钮设置和“打开应用”主进程注册表。自动化测试 66/66，桌面构建和打包冒烟通过。

仍需用户完成桌面人工复测；Maker 整份配置的安全读取—合并—写回尚未完成，因此“同步到键盘”当前会阻止覆盖写入。

### 2.2 EasyInput V2.0

EasyInput V2.0、固件别名 v2、PCB 丝印 AI Keyboard V2.1 是同一硬件基线。SoC 为 ESP32-S3R8，8 MB PSRAM、16 MB Flash。正式产品必须保留语音、历史、词库、按键映射、麦克风、网络、开机音效、AI 状态、快捷键、文字整理、账号和诊断等现有价值。

J4 四针口由原理图确认：

| J4 针位 | 丝印/网络 | MCU 侧 | 本项目用途 |
| --- | --- | --- | --- |
| 1 | 3V3 | 3.3 V 电源 | 不连接到小智 |
| 2 | RXD0 | GPIO44 / U0RXD | 接小智 TX |
| 3 | TXD0 | GPIO43 / U0TXD | 接小智 RX |
| 4 | GND | 逻辑地 | 接小智 GND |

GPIO8 是 LED、麦克风、扬声器共享电源域，不能被新功能当作单独灯开关。原生 USB 使用 GPIO19/20，板载麦克风 GPIO9/10/11，扬声器 GPIO14/13/15。

### 2.3 小智云台

当前板型是 `esp32-s3n16r8-emoji`，项目 xiaozhi 1.9.0，ESP-IDF 5.5.3 构建通过。实物模组标识为 ESP32-S3-N16R8；右侧排针顶部可见 `GND / TX / RX` 丝印，形成了 UART 接线候选的实物证据。

| 能力 | 当前静态/实物证据 | 集成边界 |
| --- | --- | --- |
| OLED | SSD1306 128×64，GPIO41/42，地址 0x3C | 可以重画大眼睛、图标、动画和简短状态 |
| yaw 舵机 | GPIO11，50°–130°，中心 90° | 真实方向和机械安全范围仍需校准 |
| pitch 舵机 | GPIO12，70°–110°，中心 90° | 真实方向和机械安全范围仍需校准 |
| 麦克风 | INMP441，GPIO5/4/6，24 kHz | 实物保留；DeskMate V1 默认不初始化 |
| 功放 | MAX98357A，GPIO15/16/7，24 kHz | 实物保留；DeskMate V1 默认不初始化 |
| 顶部 USB-C | 教程定义为烧录 | 不作为板间控制线 |
| 底部 USB-C | 教程定义为充电 | 不能当成数据口 |
| UART0/USB Serial-JTAG | 当前日志/调试 | 必须先迁移日志、再建立应用协议 |

原固件能从云端 assistant 文本或 emotion 回包进入 `EmotionResponseController → EmojiController / ServoController`。`ProcessUserCommand()` 只有定义、没有确认调用者，所以不能把“用户原话一定直接触发动作”写成现成功能。

## 3. 接线前必须理解的电气边界

### 3.1 需要准备

- 三根短而可固定的信号线；小智侧如果没有已装排针，只在焊盘、电平和方向复核后焊接，并为焊点安排绝缘与应力固定。是否增加串联保护器件由信号测量和最终接线方案决定，不在没有实测时猜阻值。
- 万用表；有条件可准备 3.3 V 逻辑分析仪。
- EasyInput 继续通过自己的 USB/电池供电；小智继续使用原装电池/电源模块或其明确支持的供电方式。

### 3.2 禁止事项

- 不连接 EasyInput J4 的 3V3 到小智 3V3/5V/VIN。
- 不把小智底部充电 USB 当数据口。
- 不从 EasyInput 3V3 给小智、舵机、功放或电池充电板供电。
- 不并联两块板的电池、5 V 或 3.3 V 电源。
- 不把“以后焊一根电源线”当成单电源方案；未来统一供电必须单独完成电源树、电流、去耦和反灌评审。
- 未迁移串口日志、未完成解码器测试前不连接 TX/RX。
- 不在两块板上电时插拔或试探针脚。

### 3.3 第一次接线步骤

1. 两块板完全关机，拔掉 USB；确认小智侧边电源开关已关闭。
2. 找到 EasyInput J4，严格按 `3V3 / RXD0 / TXD0 / GND` 丝印确认，不凭线色猜。
3. 找到小智主板候选 `GND / TX / RX` 焊盘；以实板丝印、清晰近照和连通性测量为准，不按旧照片数针脚。
4. 万用表断电通断档确认两个 GND 都属于各自逻辑地；确认 TX/RX 对地没有短路。
5. 先只接 `GND ↔ GND`。
6. EasyInput `TXD0` 接小智 `RX`；若评审决定增加串联保护器件，则按冻结后的接线图实施。
7. EasyInput `RXD0` 接小智 `TX`；若评审决定增加串联保护器件，则按冻结后的接线图实施。
8. J4 `3V3` 留空并单独绝缘。
9. 先分别给两块板供电，观察是否仍能独立正常启动；随后才运行显示-only 联动测试。

### 3.4 接线验收门

通过以下全部条件才算“可以做 UART 真机联动”：

- 两端空闲电平约为 3.3 V，没有 5 V UART。
- 两块板独立供电且共同逻辑地；没有通过 J4 反向供电。
- 小智舵机仍使用原有供电路径，没有从 EasyInput 取电。
- 两端应用日志已转到 USB Serial/JTAG，物理 TX/RX 只给 DeskMate Link 使用。
- 两端 host test 已证明错误字节、启动乱码、截断包和坏 CRC 不产生动作。
- 小智焊点有清晰照片、最终编号、绝缘和应力固定方案；焊线不会被上下叠放结构拉扯。

### 3.5 后续单电源不是简单跨板供电

V1 坚持两板独立供电。以后如需减少电源线，应从统一 5 V 输入分别建立 EasyInput 逻辑/音频支路、小智 ESP32/OLED 支路和双舵机高峰值支路，并保持共同逻辑地。必须先确认舵机空载与堵转电流、稳压器余量、功放瞬态、保险/保护、去耦和反灌路径；不得从 EasyInput J4 `3V3` 给小智或舵机供电。

## 4. 推荐的三端软件架构

```text
用户
  ├─ 语音输入键 ─→ EasyInput ─USB→ DeskMate VoiceWorkflow ─→ 当前文本框
  └─ 伴侣对话键 ─→ EasyInput ─USB→ DeskMate Conversation Mode
                                      ├─ ASR / LLM / TTS
                                      ├─ Codex / Workbody 状态
                                      └─ 高层状态/表情/动作
                                                 ↓
                                      EasyInput 总控路由
                                                 ↓ UART
                                      小智能力/状态/动作仲裁
                                         ├─ OLED 场景管理器
                                         ├─ 唯一动作仲裁器
                                         └─ 本板音频适配器（后续）
```

### 4.1 电脑端必须拥有的状态

- VoiceWorkflow：`idle → recording/listening → transcribing → organizing/thinking → outputting/speaking → completed/error`。
- Agent 状态：`offline / idle / listening / thinking / working / waiting_user / completed / error`。
- 设备状态：EasyInput 与小智分别维护 `offline / ready / busy / degraded / error`，不能由一块在线推断另一块在线。
- 模式状态：`voice_input` 与 `companion_conversation` 是同一版本化语音状态机内的不同模式，不能复制第二套录音控制器。

### 4.2 EasyInput 总控固件新增层

- `DeskMateHostAdapter`：接收桌面版本化事件，不修改现有 Host Action `0x05`。
- `DeskMateLinkCodec`：编码/解码板间帧。
- `YuntaiRouter`：只负责路由、ACK、超时、重试和能力缓存。
- `CompanionKeyAction`：实体按键产生“伴侣对话开始/停止”事件。
- 现有 USB HID、按键、旋钮、板载音频、BLE 和电源策略继续保持回归。

### 4.3 小智固件新增层

- `DeskMateLinkTransport`：UART 收发和连接状态。
- `DeskMateProtocol`：严格帧解析、版本/长度/CRC 校验和去重。
- `YuntaiCommandQueue`：有界队列与背压。
- `DisplaySceneManager`：大眼睛、对话表情和工作状态统一显示。
- `MotionArbiter`：所有舵机请求的唯一入口。
- 现有 `EmojiController`、`EmotionResponseController` 和 `ServoController` 作为执行适配器，不让新协议直接写 GPIO/PWM。

## 5. DeskMate Link v1 建议合同

### 5.1 传输参数

- 物理层：3.3 V TTL UART，三线全双工。
- 初始速率：115200 baud，8 data bits，no parity，1 stop bit，无 RTS/CTS。
- 最大帧：建议 512 bytes；控制消息通常小于 128 bytes。
- 字节序：多字节整数统一 little-endian。
- 音频：禁止放入 v1 UART 控制链。

### 5.2 帧结构草案

| 字段 | 大小 | 说明 |
| --- | ---: | --- |
| magic | 2 B | 固定 `DM`，用于从启动乱码重新同步 |
| version | 1 B | v1 为 `0x01` |
| type | 1 B | 消息类型 |
| flags | 1 B | ACK 请求、响应、错误等 |
| header_len | 1 B | 便于未来扩展 |
| payload_len | 2 B | 负载长度，超过上限立即丢弃 |
| sequence | 4 B | 请求序号；重试保持不变 |
| payload | N B | 结构化负载 |
| crc16 | 2 B | CRC16-CCITT，覆盖头和负载 |

### 5.3 v1 最小消息集

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `hello` | 双向 | 协议版本、设备角色、启动代次 |
| `get_capabilities` | 总控→云台 | 查询屏幕、动作、音频和协议能力 |
| `get_status` | 总控→云台 | 查询当前场景、动作、错误和连接状态 |
| `set_agent_state` | 总控→云台 | 显示 Codex/Workbody 工作状态 |
| `set_expression` | 总控→云台 | 设置白名单表情，可带持续时间 |
| `play_action` | 总控→云台 | 执行白名单离散动作 |
| `stop_motion` | 总控→云台 | 最高优先级停止并进入安全状态 |
| `center_head` | 总控→云台 | 安全回中 |
| `ack` | 云台→总控 | accepted / completed / rejected |
| `error` | 云台→总控 | busy / invalid / unsupported / unsafe / timeout |
| `heartbeat` | 双向 | 在线、重启和超时检测 |

### 5.4 重试与安全规则

- 本地链路建议 250 ms 未收到 accepted ACK 时重试，最多 2 次；重试必须沿用 sequence。
- 云台缓存最近 sequence，重复包只重发结果，不重复执行动作。
- 长动作先回 `accepted`，结束再回 `completed`。
- 连续 3 个心跳周期未收到对端，进入 degraded/offline；进行中的危险动作停止并回到安全策略。
- 未知版本、未知 type、超长帧、坏 CRC、无效枚举和任意文本都不得触发动作。
- `stop_motion`、故障和人工回中不可被普通动画队列阻塞。

## 6. 两种语音功能如何共存

### 6.1 模式 A：语音输入

用途是把语音识别结果放进 Codex、Workbody、记事本或其他文本框。

```text
EasyInput 语音输入键
  → EasyInput 板载麦克风采集
  → DeskMate 开始/结束录音
  → ASR + 可选文字整理
  → 历史先保存
  → 原输入框；失败回退剪贴板
```

它不启动伴侣人格、不播放连续对话 TTS，也不让云台抢焦点。小智最多显示短暂“正在听/已完成”状态。

### 6.2 模式 B：伴侣实时对话

新增一个可配置实体按键作为 `companion_talk_toggle`：按一次唤醒/开始，按一次结束或打断；不要求先说“你好小智”。最终由 DeskMate App 管理会话、模型、记忆、工具和安全权限。

V1 已冻结为：EasyInput 板载麦克风负责用户语音，EasyInput 板载扬声器播放本地 TTS；小智只显示 listening/thinking/speaking 表情并执行后续安全动作。电脑麦克风和扬声器只作为开发期回退，不是正式默认路径。小智本板麦克风、功放和扬声器保留但默认不初始化。

实现顺序：

1. 先用电脑音频完成 ConversationWorkflow 状态机、取消、打断和错误恢复。
2. 接入 EasyInput 板载麦克风，锁定录音、ASR、历史和文字输入旧功能不回归。
3. 接入 EasyInput 扬声器播放 TTS 和提示音，验证 GPIO8 共享电源域、回声和音频互斥。
4. 最后让小智按同一会话状态显示表情；UART 仍只传高层状态和控制。

UART 115200 的有效吞吐约 11.5 KB/s，而 24 kHz、16-bit、单声道 PCM 一路约 48 KB/s，因此 UART v1 不承担实时音频。不要为了“一根线全包”破坏已稳定的控制链。

### 6.3 原小智云端功能怎么处理

原来的“你好小智”云端固件只保留为早期功能对照、恢复镜像和硬件验收基线，不作为最终 DeskMate 固件的长期双模式。DeskMate 本地对话达到连续稳定、断网可解释、隐私和工具能力明确后，正式产品不再依赖原小智云端；恢复镜像和来源证据仍保留在产品仓之外。

## 7. 本地长期记忆与说话人识别

### 7.1 产品目标

DeskMate 的长期价值不只是回答一次问题，而是逐渐理解使用者：知道当前是谁在说话、记得家人的基本资料和偏好、能关联过去发生的事情，并在一年、两年后仍可以查回、解释、纠正或删除。

这里的“本地”首先指记忆、身份资料、检索索引和权限由 DeskMate Windows App 在本机管理，不再依赖 `xiaozhi.me` 账号侧记忆。ASR、LLM 和 TTS 可以分别选择本地模型或云端适配器；使用云端时只发送本轮必要、经过用户许可的最小上下文，长期记忆数据库仍留在本机。

### 7.2 需要区分的四类数据

| 类型 | 示例 | 默认策略 |
| --- | --- | --- |
| 人物档案 | 名字、称呼、家庭关系、偏好 | 明确确认后长期保存 |
| 情节记忆 | 某次旅行、孩子比赛、一次重要聊天 | 自动生成候选摘要，用户确认或按设置保存 |
| 语义记忆 | 长期兴趣、习惯、常用设备、目标 | 带来源、置信度和最后更新时间 |
| 会话临时上下文 | 本轮对话内容、正在执行的任务 | 会话结束后按策略清理或摘要，不默认永久保留原文/录音 |

每条长期记忆至少包含：memory_id、人物 profile_id、类别、摘要、来源会话、创建/更新时间、置信度、敏感等级、有效期、是否用户确认、版本和删除状态。记忆不能只是一段不可追溯的大文本。

### 7.3 说话人识别

每个家庭成员建立独立本地 profile。初次登记时由本人或监护人明确同意，采集多段正常语音生成本地声纹向量；默认不长期保存原始登记录音。识别结果分为“已识别人物 / 不确定 / 新说话人”，置信度不足时必须询问“请问你是谁”，不能强行猜。

声纹属于敏感生物特征：

- 本地加密保存，密钥由 Windows 当前用户安全存储保护。
- 每个 profile 可查看、重新登记、导出和彻底删除。
- 儿童资料由监护人管理，默认使用更严格的保存和云端发送策略。
- 声纹只用于个性化和记忆归属，不作为付款、删除数据、烧录设备、开门或其他高风险操作的唯一身份凭证。
- 不承诺防录音回放或专业伪造；高风险操作仍需要屏幕/实体确认。

### 7.4 记忆写入和取回

```text
语音/文本
  → 说话人候选
  → 当前会话
  → 记忆候选提取
  → 隐私/敏感规则
  → 用户确认或自动保存策略
  → 本地结构化数据库 + 本地检索索引

下一轮问题
  → 识别当前人物
  → 按人物、时间、主题和权限检索
  → 只取少量相关摘要
  → 交给当前 LLM 生成回答
  → 显示“本次用了哪些记忆”
```

用户要能直接说：“记住这件事”“这不是我的信息”“忘掉刚才那件事”“把关于我的记忆给我看”“我是谁”。软件设置页需要人物管理、记忆时间线、搜索、修改、合并、忘记、导出、备份和恢复入口。

### 7.5 一两年后仍可用的工程条件

- 使用版本化本地数据库，优先 SQLite；字段迁移必须有自动化测试和回滚备份。
- 记忆原文、摘要、向量索引和人物档案分层存储，不能因更换 embedding/LLM 就丢失原始结构化事实。
- 提供加密备份、恢复和跨电脑迁移；备份包不包含 API Key，默认不包含原始录音。
- 定期做重复记忆合并、冲突标记和过期清理；新事实不能无声覆盖旧事实。
- 回答时展示来源时间和不确定性；用户纠正拥有最高优先级。
- 任何自动“记住”都必须有可见提示和总开关；密码、验证码、Wi-Fi、支付、医疗等敏感信息默认不进入长期记忆。

### 7.6 与硬件的关系

长期记忆和声纹识别属于 DeskMate App，不放进 EasyInput NVS，也不放进小智 Flash。两块板只接收本轮需要的脱敏人物标签和高层状态，例如 `speaker=owner`、`speaker=family_2`、`expression=happy`；不传人物声纹向量、完整聊天历史或私密记忆。

## 8. OLED 大眼睛、表情和工作状态

SSD1306 是 128×64 单色屏，完全可以重画为两个大眼睛、简短图标和动画，但不适合堆大量文字。建议建立场景管理器，不让各功能直接抢屏。

### 8.1 显示优先级

```text
安全故障/离线
  > 伴侣语音对话表情
  > 用户直接动作反馈
  > Codex / Workbody 工作状态
  > 待机大眼睛和随机眨眼
```

对话表情带 TTL，到期后自动恢复之前的 Agent 状态；不能永久覆盖“正在工作”或错误提示。

### 8.2 建议状态视觉

| 状态 | 大眼睛/表情建议 | 辅助标识 |
| --- | --- | --- |
| offline | 闭眼或断线眼 | `OFF`/断链图标 |
| idle | 正常双眼、随机眨眼 | Agent 短名 |
| listening | 放大瞳孔或声波 | 麦克风图标 |
| thinking | 左右扫描或点状动画 | `...` |
| working | 聚焦、眉形收紧 | 齿轮/进度点 |
| waiting_user | 抬眼、问号 | `?` |
| completed | 笑眼/眨眼 | 勾号 |
| error | 担忧眼/X 眼 | `ERR` |

第一版先做静态帧和轻量眨眼；确认 LVGL、队列、内存和帧率稳定后再增加动画。Codex 与 Workbody 的状态来源必须是桌面真实适配器，不能由小智自己猜。

## 9. 舵机动作与唯一仲裁器

### 9.1 白名单动作

第一版只接受：`center`、`nod`、`shake`、`look_left`、`look_right`、`look_up`、`look_down`、`blink`、`cry`、`spin`、`dance`。LLM 输出结构化动作意图，再由白名单映射；任意自然语言不能直接成为执行命令。

### 9.2 动作优先级

```text
急停/硬件故障
  > 人工回中/安全恢复
  > 对话离散动作
  > 人脸连续跟踪
  > 待机随机动作
```

对话动作期间暂停人脸跟踪；动作结束后平滑恢复。所有动作必须经过：软件限位、死区、最大步长、最大速度、命令超时、忙碌状态、队列上限、丢脸回中和高优先级急停。

### 9.3 真机开放顺序

1. 只读当前状态，不动舵机。
2. 屏幕表情联动。
3. 单轴回中。
4. 从中心开始 1～2° 小步，记录实际正负方向。
5. 现场缩小为实物安全软限位，不直接采用源码最大范围。
6. 一次点头。
7. 摇头、左右看、上下看。
8. 最后才评估转圈、跳舞和连续跟踪。

## 10. “一个功能一个功能锁定”的工程规则

每个功能都按同一张功能卡推进：

1. 写清用户可见行为和不做什么。
2. 写纯逻辑测试；错误输入必须 fail closed。
3. 实现最小代码，不顺手重构其他模块。
4. 跑本模块测试和构建。
5. 用模拟器验证正常、错误、重复、超时和断线。
6. 需要真机时，先展示设备/端口/芯片/固件授权卡，由用户明确确认。
7. 做人工验收并记录证据。
8. 更新进展、稳定决策和回归矩阵，才标为 locked。

锁定不是“永远不改”，而是以后任何修改都必须先跑回归；若有意改变旧行为，要更新规格和测试并说明迁移影响。

### 10.1 相似功能包

开发按以下功能包分组，一个包关闭前不并行打开后面的包：

| 功能包 | 放在一起开发的内容 | 包末必须做的联调 |
| --- | --- | --- |
| A 桌面输入 | 语音输入、目标窗口、历史、快捷键 | 软件 + EasyInput 实体语音键完整回归 |
| B 键盘配置 | 八键、旋钮、打开应用、完整配置读写 | 本机保存 + 板上确认 + 旧按键矩阵 |
| C 板间基础 | codec、模拟器、UART、能力/状态 | 两板重启、断线、20 次 display-only 联动 |
| D 屏幕状态 | 大眼睛、Agent 状态、场景优先级 | 软件状态 → 总控 → 小智画面 + 旧通信回归 |
| E 伴侣对话 | 对话按键、ASR/LLM/TTS、取消/打断 | 语音输入模式与伴侣模式互不串线 |
| F 本地记忆 | 人物档案、记忆库、检索、声纹、隐私 | 多人物对话、误识别、删除、备份恢复 |
| G 安全动作 | 回中、急停、限位、点头，再扩其他动作 | 屏幕/语音/通信全回归 + 机械故障矩阵 |
| H 扩展设备 | 摄像头、人脸跟随、温湿度等 | 拔掉扩展设备后核心主链仍全部通过 |

每个功能包结束时必须连续执行：本包定向测试 → 两端或三端联通测试 → 之前所有 locked 功能回归 → 记录版本和证据。任一步失败就留在当前包修复，不能先跳到新功能。

### 10.2 回归节奏

- 每完成 1 个功能：跑该功能定向测试 + 所属模块 build。
- 每完成 2～3 个功能：跑该模块全量测试 + 关键真机矩阵。
- 每完成一个跨端里程碑：三端完整构建、协议向量、断线/重启和历史能力回归。
- 每次烧录：一次只改变一块板，先独立验收，再连接两板。

## 11. 详细开发阶段

### 阶段 0：冻结硬件、软件与恢复基线

目标：任何后续修改都能退回；本阶段不烧录、不焊线。

- DeskMate：记录当前 Git 状态、66/66 测试、桌面构建和打包冒烟。
- EasyInput 参考：固定提交、IDF 5.5.5、板型、恢复固件、分区和未提交差异。
- 小智参考：记录源码清单/哈希、IDF 5.5.3、板型、分区、当前云端固件和恢复方式。
- 冻结本书第 1～3 章和 `docs/architecture/deskmate-v1-hardware-baseline.md`。

通过门：三个系统都能独立回到已知可用状态；硬件选择、禁用项和独立供电已书面确认。

### 阶段 1：建立正式模块和兼容合同

目标：让另一台无硬件笔记本可以在不猜目录、不碰设备的情况下开工。

```text
firmware/easyinput-controller/
firmware/xiaozhi-yuntai/
contracts/deskmate-host/
contracts/deskmate-link/
tools/simulators/
docs/provenance/
```

- 每个固件模块补局部 `AGENTS.md`、README、精确 IDF、host test 和 build 入口。
- 根级仍只有一套 `flow/`、`docs/` 和 hook，不嵌套第二个 Git。
- 冻结 EasyInput 现有按键、旋钮、USB/BLE、配置、Host Action、音频和 GPIO8 行为合同。
- 逐文件记录参考来源、版本/哈希、许可证、采用方式和目标路径。

通过门：两台电脑从同一 Git 提交能复现目录、host test 和构建；参考工程仍在产品仓之外。

### 阶段 2：无硬件笔记本开发 EasyInput 总控固件

目标：先完成可测试、可构建、但尚未冒充真机通过的 EasyInput 正式固件候选。

按小功能包推进：

1. 板型声明、构建骨架和 host test。
2. 八键、旋钮、防抖和 USB HID 兼容逻辑。
3. 完整配置读取/合并/写入、CRC 和保存确认。
4. Host Action、状态、断线和重启恢复。
5. EasyInput 麦克风、扬声器、LED 和 GPIO8 共享电源仲裁。
6. DeskMate Link 编码器、严格解析器、超时状态机和假 UART sink；暂不接小智。

每包都执行定向测试、固件 host test、完整回归和 IDF 5.5.5 build。无硬件电脑只能标记 `TEST_CONFIRMED/BUILD_CONFIRMED`，不得写“真机完成”。

通过门：分支已推送 GitHub；提交小、来源清楚、测试和构建证据齐全；没有烧录脚本自动执行路径。

### 阶段 3：有硬件电脑独立审计 EasyInput 候选

目标：在接触开发板前，用第二套视角证明代码值得进入真机阶段。

- 从 GitHub 获取远端任务分支，不接受聊天中粘贴的大段代码或手工复制的 build 目录。
- 审查 GPIO、BOOT、USB、音频、GPIO8、分区、NVS、许可证和来源记录。
- 重跑 host test、IDF build、静态安全检查和与参考行为的差异矩阵。
- 发现问题退回原任务分支修复；审计者不顺手重写整个模块。

通过门：独立测试与构建通过；评审结论为 PASS；所有真机风险列入授权卡。

### 阶段 4：EasyInput 单板真机验收

目标：先把 EasyInput 新固件和原有硬件能力全部锁定，再让桌面软件依赖它。

- 经本轮明确授权后才识别端口、备份恢复信息和烧录。
- 逐项验证八键、旋钮、USB/BLE HID、配置、Host Action、板载麦克风、扬声器、LED、电源和断线恢复。
- 本阶段不连接小智 TX/RX，不做舵机动作。
- 每出现一个真机问题，就回到对应小功能包修复并重跑旧矩阵。

通过门：EasyInput 新固件在目标实板连续通过完整矩阵，且能够恢复到原固件。

### 阶段 5：DeskMate 软件与新 EasyInput 闭环

目标：软件不再只对原始 Maker 固件做演示，而是与 DeskMate 正式总控固件形成读写闭环。

- 锁定语音输入、目标窗口输出、历史复制、快捷键录制、八键、旋钮、打开应用和诊断。
- 完成“读取完整配置 → 显示差异 → 合并修改 → 用户确认 → 写入 → bytes/CRC/saved 确认”。
- 先接 EasyInput 麦克风，再接扬声器；每次都回归文字输入和所有实体键。

通过门：桌面人工清单全部通过；配置同步前后旧按键、网络、音频和 Host Action 均不回归。

### 阶段 6：冻结 DeskMate Link v1 与模拟器

目标：三端先说同一种协议，不接线、不焊接。

- 冻结帧、消息、ACK、错误、超时、重试、去重、重启和兼容策略。
- 生成 C/C++/JavaScript 共用黄金向量。
- 建立模拟总控与模拟云台。
- 第一条消息只做 `get_capabilities/get_status`，第二条只改变 OLED 表情。

通过门：正常、截断、坏 CRC、超长、重复 seq、未知版本在三端结果一致。

### 阶段 7：无硬件笔记本开发小智执行固件

目标：完成不依赖云端音频的 DeskMate 小智固件候选。

1. 严格解码器、有界队列和 host test。
2. `get_capabilities/get_status`，不动屏幕和舵机。
3. DisplaySceneManager 和 idle/thinking/working/completed/error 静态场景。
4. 唯一 MotionArbiter、`stop_motion`、回中、限幅和忙碌状态，先使用模拟舵机。
5. 日志迁移到 USB Serial/JTAG，应用 UART 使用冻结的物理焊盘映射。
6. DeskMate 模式不初始化小智 INMP441、MAX98357A 和云端会话。

通过门：host test 和 IDF 5.5.3 build 通过；错误包不改变场景或模拟舵机；仍未声明真机通过。

### 阶段 8：有硬件电脑审计并验收小智单板

目标：先验证执行板本身，再允许板间连接。

- 独立审查来源、分区、日志、OLED、动作仲裁和音频禁用边界。
- 经烧录授权后先验证启动、能力和 OLED，不给舵机动作命令。
- 另行授权后才从中心开始做单轴 1～2° 小步校准，记录方向和安全限位。

通过门：屏幕、重启、错误包和急停路径稳定；中心、方向、软限位有现场证据。

### 阶段 9：第一次三线物理连接

目标：只证明一条无机械风险消息跨板。

- 完成焊盘近照、GND 连通性、TX 空闲电平、绝缘和应力固定评审。
- 断电焊接/连接 `TX/RX/GND`，J4 `3V3` 留空，两板独立供电。
- EasyInput 发送 `get_capabilities`，小智返回能力。
- EasyInput 发送 `set_agent_state=working`，小智只显示工作眼睛，不播放声音、不动舵机。
- 连续 20 次触发，并分别重启 EasyInput、小智和电脑。

通过门：不丢、不重、不误触发；坏包不改变屏幕；任一端重启后重新握手。

### 阶段 10：双向 ACK、状态与三端软件

目标：软件能看到真实执行结果。

- DesktopBridge 向 EasyInput 发高层意图。
- EasyInput 转发给小智并等待 ACK/完成。
- UI 区分“已发送 / 总控已接收 / 云台已接受 / 已完成 / 失败”。
- 接入一个真实 AgentStatusAdapter，先选 Codex 或 Workbody。

通过门：UI、总控 seq、小智 ACK 和真实屏幕对应同一事件。

### 阶段 11：EasyInput 本地伴侣对话

目标：不用唤醒词，由实体键启动 DeskMate 本地对话。

- 先完成 ConversationWorkflow 和电脑音频回退。
- 再把一个 EasyInput 键配置为 `companion_talk_toggle`。
- 正式 V1 使用 EasyInput 麦克风和扬声器；小智只显示 listening/thinking/speaking。
- 录音、模型、TTS 或网络失败必须可取消并回 idle，不影响文字语音输入键。

通过门：文字输入与伴侣对话各连续 10 次，不串模式、不抢焦点、不丢历史。

### 阶段 12：安全动作闭环

目标：完成一个动作，而不是一次加入全部动作。

- 先完成 `center_head` 和 `stop_motion`。
- 使用现场冻结的方向、中心和软限位。
- 把 completed 映射为一次安全点头。
- 之后按白名单逐个加入摇头、左右看和上下看；转圈、跳舞最后评估。

通过门：重复包不重复动作；忙碌和急停有效；断线没有危险持续运动。

### 阶段 13：大眼睛与 Agent 状态系统

目标：让屏幕成为真正的产品界面。

- 做 idle、blink、focus、listen、think、complete、error 大眼睛帧。
- 表情和 Agent 状态通过场景优先级叠加，不互相永久覆盖。
- 每增加一个动画都测内存、队列、帧率、切换和长时间运行。

通过门：一小时状态切换无卡死；对话结束能恢复先前 Agent 状态。

### 阶段 14：本地长期记忆与说话人识别

目标：让伴侣认识家庭成员并形成可管理的长期记忆。

1. 单人物 profile、显式“记住/忘记”和 SQLite 迁移测试。
2. 记忆候选、来源/置信度、时间线、搜索和冲突纠正。
3. 第二人物先手动选择，证明记忆严格隔离。
4. 最后增加本地声纹登记；低置信度必须询问。
5. 加密备份、恢复、导出和彻底删除。

通过门：两个人物各 20 轮不串记忆；可纠正、可删除、可恢复；关闭云端后仍可查询。

### 阶段 15：统一供电、摄像头和传感器扩展

目标：核心主链稳定后才改变硬件范围。

- 单电源版本先设计统一 5 V 输入和三条独立负载支路，不从 J4 `3V3` 跨板供电。
- 摄像头首版接电脑，人脸检测输出 `x/y/confidence/timestamp`。
- 小智只接收高层目标，MotionArbiter 负责死区、滤波、限速和丢脸回中。
- 温湿度等传感器一次只加一个，经能力协商报告。

通过门：拔掉新增硬件后，语音、按键、屏幕、两板通信和安全回中仍全部通过。

## 12. 三端验收矩阵

| 层级 | Windows 软件 | EasyInput 总控 | 小智云台 |
| --- | --- | --- | --- |
| 纯逻辑 | 状态机、模式、配置迁移、ACK 展示 | codec、路由、重试、按键事件 | parser、场景、动作仲裁、限位 |
| 构建 | `npm test`、`npm run build:desktop` | host test + IDF 5.5.5 build | host test + IDF 5.5.3 build |
| 模拟 | mock DeviceAdapter | fake UART sink | PC 协议发送器 |
| 单板真机 | USB/目标窗口/历史/设置 | 八键、旋钮、HID、音频、UART 电平 | OLED、按键、音频、中心/限位 |
| 两板 | UI 到总控状态 | 发送/ACK/超时 | 能力、显示、ACK、故障 |
| 三端 | 意图和可见结果 | 单通道路由 | 表情、动作、安全恢复 |

每个矩阵项必须记录：发现数、执行数、通过数、失败数、未测数。构建通过不能冒充真机通过，用户观察也不能冒充电气测量。

## 13. 设备操作与烧录规则

- 默认开发不授权烧录。每次写入前重新发现端口，读取芯片和 MAC，向用户展示“目标端口 + 芯片 + MAC”，用户明确确认后才执行。
- EasyInput 当前板进入下载模式的权威操作是：开机状态短按并松开 BOOT；退出时关机再开机。它没有用户独立 RESET/EN 键。
- 小智使用顶部 USB-C 烧录；底部 USB-C 只充电。具体 BOOT/RESET 恢复按该实板和当前任务证据执行，不能套 EasyInput 流程。
- 一次只烧一块板；烧完先独立验收，再连接两板。
- 不执行 `erase_flash`、不写 eFuse、不盲目 fullclean、不使用小智旧 `scripts/flash.sh`。
- 任何舵机动作都需要本轮单独确认；固件开发授权不等于机械动作授权。

## 14. 两台电脑、两个开发账号和 GitHub 协作方式

两台电脑不是“一个写完、另一个最后才看”，而是明确分成生产端和验收端：

| 角色 | 无硬件笔记本 | 当前有硬件电脑 |
| --- | --- | --- |
| 主要职责 | 代码实现、host test、模拟器、IDF build、文档增量 | 独立代码审计、重复构建、设备授权、烧录、真机联调、最终集成 |
| 能给出的最高证据 | `TEST_CONFIRMED`、`BUILD_CONFIRMED` | `REVIEW_CONFIRMED`、`DEVICE_CONFIRMED`、`USER_OBSERVED` |
| 禁止事项 | 不声称真机通过；不猜端口、Flash、舵机和焊点 | 不跳过审计直接烧录；不在脏工作区覆盖远端成果 |

### 14.1 三套资料怎样放到另一台电脑

- `F:\Codex\deskmate` 必须从 GitHub **clone**，以后只通过提交、分支和 Pull Request 交换；不要反复整目录覆盖。
- `F:\Codex\easyinput-wzm\easy-input-maker` 是只读 Maker 参考，使用固定提交 `7619bd1...`；不要在该目录开发 DeskMate 正式固件。
- `F:\Codex\xiaozhi-yuntai` 当前没有可靠 Git 身份，可以初次复制只读快照，但必须连同技术地图和文件哈希保持一致；不要把其 build 目录复制进 DeskMate。
- 两台电脑都保持英文 ASCII 目录。API Key、Wi-Fi、录音、NVS、设备标识和构建产物不通过 GitHub 交换。

### 14.2 每个任务的 GitHub 流程

1. 有硬件电脑在 `flow/tasks/` 写一张小任务卡，明确输入、允许修改路径、禁止范围、验证命令和交付门。
2. 无硬件笔记本先同步 `main`，创建独立分支，例如 `codex/easyinput-input-foundation`；一个分支只做一个小功能包。
3. 实现端写测试、代码和来源记录，运行定向测试、全量测试和构建。
4. 实现端把交接增量写到 `flow/progress.md` 顶部，提交并推送分支；不要提交 `build/`、固件镜像、录音或本机路径。
5. 有硬件电脑从 GitHub 获取该分支，在独立 worktree 或干净审计目录重跑测试和构建，检查 diff、GPIO、协议、许可证和恢复能力。
6. 审计失败：把具体证据退回原分支修改，不叠加下一功能。审计通过：才允许申请单板真机操作。
7. 真机验收通过后记录端口、固件版本、测试矩阵和用户观察的脱敏摘要，再合并到 `main`。
8. 下一项任务必须从最新 `main` 开新分支，不能从尚未验收的旧分支继续堆功能。

### 14.3 可以并行什么，不能并行什么

可以并行：实现端开发下一个**不依赖真机结论**的纯逻辑测试或文档；验收端审计已经提交的上一包。不能并行：两台电脑同时修改同一固件模块、同一协议版本或同一任务卡；不能在 EasyInput 固件尚未验收时，让桌面按猜测的固件行为继续扩展。

用户负责：确认实物、按要求断电/接线/按键、观察屏幕和机械现象、对每次烧录、焊接和危险动作给明确授权。Codex 负责：读取规则和基线、修改代码、写测试、构建、做模拟器、列出设备授权卡、分析日志、更新文档和回归矩阵。

每一轮只给一个焦点，例如：

> 只在 EasyInput 正式固件模块实现八键/旋钮纯逻辑和 USB HID host test；本轮不接小智、不烧录、不改音频和分区。完成后运行定向测试、完整测试、IDF build，更新来源记录和 flow/progress.md，并推送独立任务分支供另一台电脑审计。

## 15. 现在马上开始的顺序

1. 把 `deskmate` 从 GitHub clone 到无硬件笔记本；复制或克隆两套只读参考，并核对提交/哈希。
2. 在有硬件电脑保存当前三套可恢复基线；暂不焊接、不烧录。
3. 冻结正式模块目录、EasyInput 兼容合同和逐文件来源/许可证记录。
4. 无硬件笔记本先开发 EasyInput 正式固件的小功能包：构建骨架 → 八键/旋钮/HID → 完整配置 → Host Action/状态 → 板载音频 → Link 假 UART。
5. 每个包推送独立分支；有硬件电脑逐包审计、重跑测试和构建。不要等“整个固件全部写完”后一次性审计。
6. 审计通过后，在有硬件电脑申请 EasyInput 单板烧录和逐项真机验收；失败立即退回当前包。
7. EasyInput 新固件锁定后，再完成 DeskMate 配置、按键、语音输入和板载扬声器的真实闭环。
8. 冻结 DeskMate Link v1、黄金向量和模拟器；随后让无硬件笔记本开发小智执行固件。
9. 小智经过独立审计和单板 OLED/安全动作验收后，再拍焊盘近照、测量电平并申请三线焊接。
10. 第一次板间联动只做能力查询和 OLED 显示；完成 ACK/状态回读后再接真实 Agent 状态。
11. 做 EasyInput 本地伴侣对话、大眼睛和一个安全点头；随后单独进入本地记忆/人物识别。
12. 主链全部稳定后，才讨论统一供电、摄像头、温湿度和其他扩展。
